클라우드 인프라 프로비저닝부터 데이터베이스 모델링, 프론트엔드, 백엔드 파이프라인까지

자격증공부.com
PHASE 01

계획 : 왜 서버리스를 포기했는가?

  • 진정성 있는 프로젝트 목표 나와 동기들이 실제로 사용할 수 있는 자격증(SQLD, OCP 등) CBT 플랫폼을 기획했습니다. 단순히 보기 좋은 화면을 만드는 것을 넘어, 대규모 데이터가 오가는 실무형 파이프라인을 직접 경험하고 싶었습니다.

  • 어려운 길을 선택한 기술적 의사결정 쉽고 빠르게 배포할 수 있는 Vercel이나 Supabase 같은 서버리스 환경의 유혹을 뿌리쳤습니다. 인프라의 로우레벨부터 직접 통제해보기 위해 OCI(Oracle Cloud) 기반의 단일 DB 아키텍처를 과감하게 채택했습니다.

  • 기획의 본질: 통제력 증명 프론트엔드의 화려함보다는 '지저분한 외부 데이터를 어떻게 수집하고, 예외 없이 검증하며, 무결성을 유지한 채 DB에 적재할 것인가?'라는 DBA 본연의 트랜잭션 제어 역량을 어필하는 것에 집중했습니다.

PHASE 02

설계 : 3NF 정규화 및 ERD 도출

데이터베이스 설계의 정석인 3단계를 거쳤습니다.
① 개념 모델링으로 사용자, 자격증, 문제 등 핵심 비즈니스 관계를 정의하고,
② 논리 모델링에서 제3정규형을 적용해 보기(Options)를 별도 자식 테이블로 완벽히 분리했습니다. 이를 통해 5지선다 확장성을 확보하고 단답형 문제의 빈 컬럼(NULL) 낭비를 막았습니다.
③ 물리 모델링 단계에서는 HTML 데이터를 안정적으로 수용하기 위해 CLOB 타입을 적용하고, 자식 테이블에 ON DELETE CASCADE를 걸어 참조 무결성을 보장하는 등 오라클 OCI 환경에 맞춘 최종 아키텍처를 완성했습니다.

PHASE 03

위기 및 해결 : 더티 데이터와의 전쟁

트랜잭션 롤백과 데이터 오염

구조화되지 않은 엑셀 기출문제를 운영 테이블에 직행시키자, 필수 값 누락이나 오타(예: 'LM') 1건 때문에 전체 트랜잭션이 롤백되는 심각한 장애가 발생했습니다.

외부 데이터가 바로 적재되지 않도록 QUESTION_STG 테이블을 격리 구축했습니다. PL/SQL 검증과 SAVEPOINT를 활용해 에러 Row만 마킹하는 닫힌 루프(Closed-loop)를 완성했습니다.

거대 이미지로 인한 스토리지 병목

지문과 해설에 포함된 수많은 고화질 이미지를 RDBMS(BLOB)에 직접 밀어 넣으려다 보니, 백업 용량 급증과 실시간 조회 시 I/O Wait 부하가 우려되었습니다.

정적 자원(Media)을 OCI Object Storage 버킷으로 분리 업로드하고, DB에는 <img src="..."> 형태의 짧은 URL 문자열만 저장하여 트랜잭션 비용을 획기적으로 낮췄습니다.
PHASE 04

결과 : 24/7 엔터프라이즈 아키텍처 완성

  • 운영 DB 불량 데이터 유입률 0% STG 테이블 격리와 철저한 정규화 로직을 통해, 사용자가 언제 접속하더라도 깨지거나 누락된 문제 없이 쾌적하게 모의고사를 풀 수 있는 100% 무결성을 확보했습니다.

  • 인프라 자립과 무중단 배포 OCI Compute VM 인스턴스에 Nginx 리버스 프록시와 PM2를 결합하여, 백엔드 Oracle Wallet 커넥션 풀을 안정적으로 관리하며 단 한 번의 중단 없는 24시간 서비스 운영을 이뤄냈습니다.

  • 엔진 레벨의 쿼리 튜닝 ROW_NUMBER() OVER(PARTITION BY) 분석 함수를 활용해 애플리케이션 단이 아닌 DB 엔진에서 종목별 출제 비율을 커팅(Cutting)하도록 최적화하여 In-Memory 정렬 부하를 원천 차단했습니다.
