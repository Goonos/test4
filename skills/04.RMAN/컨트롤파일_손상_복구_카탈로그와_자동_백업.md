```sql
-- 컨트롤파일이 모두 손상되었다.
-- 카탈로그를 사용해 복원하는 경로를 먼저 수행한다.
-- 이어서 카탈로그 없이 자동 백업에서 복원하는 경로를 수행한다.
-- 두 방식의 차이와 DBID의 역할을 확인한다.
-- 복구 유형 : 완전 복구, 전면 중단, RESETLOGS 강제

**사전 조건**
[세션: RMAN (Target + Catalog 동시 접속)]
SHOW CONTROLFILE AUTOBACKUP;
컨트롤파일 자동 백업(AUTOBACKUP) 기능이 켜져(ON) 있는지 확인합니다.

BACKUP DATABASE TAG 'BASE_158' PLUS ARCHIVELOG;
실습을 위한 베이스 백업을 수행합니다. 백업이 완료되면 컨트롤파일과 SPFILE의 자동 백업(Autobackup) 조각이 함께 생성됩니다.

**초기 상태 확인**
[세션: SQL*Plus (SYSDBA)]
SELECT dbid, name FROM v$database;[중요] 현재 데이터베이스의 DBID(예: 1200530011)를 반드시 별도로 기록해 둡니다. 카탈로그 없이 컨트롤파일을 복구할 때 생명줄이 됩니다.

SELECT name FROM v$controlfile;
컨트롤파일들이 다중화되어 있는 현재 경로들을 확인합니다.

CREATE TABLE hr.rec158(id NUMBER, memo VARCHAR2(30)) TABLESPACE users;INSERT INTO hr.rec158 VALUES (1, 'after backup');COMMIT;ALTER SYSTEM ARCHIVE LOG CURRENT;

**장애 유발 : 컨트롤파일 전체 삭제**
[세션: SQL*Plus (SYSDBA)]
SHUTDOWN ABORT

!rm -f /u01/app/oracle/oradata/orcl/ *.ctl /u02/oradata/orcl/ *.ctl
운영 중인 모든 컨트롤파일을 OS 상에서 삭제하여 컨트롤파일 전손(전체 손실) 장애를 유발합니다.

**증상 관찰 및 진단**
[세션: SQL*Plus (SYSDBA)]
STARTUP
데이터베이스 기동을 시도하지만, 오라클의 두뇌(컨트롤파일)가 없으므로 NOMOUNT 단계까지만 올라가고 ORA-00205 에러를 뱉으며 멈춥니다.

!tail -5 /u01/app/oracle/diag/rdbms/orcl/orcl/trace/alert_orcl.log
알럿 로그를 통해 ORA-00210, ORA-00202, Linux Error: 2 (컨트롤파일을 찾을 수 없음) 에러를 정확히 진단합니다.

**복구 절차 1 : 카탈로그를 사용하는 경우**
[세션: RMAN (Target + Catalog 동시 접속)]
RESTORE CONTROLFILE;
(현재 DB는 NOMOUNT 상태) 카탈로그 DB에 접속해 있으므로 RMAN이 DBID와 백업 경로를 모두 알고 있습니다. 단 한 줄의 명령어로 가장 최신의 자동 백업 컨트롤파일을 다중화된 모든 경로(control01.ctl, control02.ctl 등)에 알아서 뿌려(복원해) 줍니다.

ALTER DATABASE MOUNT;
컨트롤파일이 복원되었으므로 DB를 MOUNT 상태로 올립니다.

ALTER DATABASE OPEN;
바로 오픈을 시도하면 ORA-01589 에러가 발생합니다. 방금 복원한 컨트롤파일의 SCN(과거)이 현재 디스크에 있는 데이터파일의 SCN(최신)보다 오래되었기 때문에 리두를 들이부어(RECOVER) 시점을 맞춰야 합니다.

RECOVER DATABASE;
아카이브 및 온라인 리두 로그를 적용하여 최신 시점으로 동기화합니다.

ALTER DATABASE OPEN RESETLOGS;
과거의 백업 컨트롤파일을 사용해 복구했으므로 반드시 RESETLOGS 옵션을 주어 데이터베이스를 오픈해야 합니다. (이와 동시에 카탈로그에 새로운 인카네이션이 자동으로 등록됩니다.)

**복구 절차 2 : 카탈로그 없이 자동 백업(Autobackup)을 사용하는 경우**
(테스트를 위해 다시 BASE_158B 백업 생성 -> 데이터 입력 -> SHUTDOWN ABORT -> 모든 .ctl 파일 삭제 -> STARTUP NOMOUNT 상태로 만듭니다.)

[세션: RMAN (Target 단독 / nocatalog)]
RESTORE CONTROLFILE FROM AUTOBACKUP;
카탈로그 없이 자동 백업에서 복원하려 시도하면 RMAN-06495 에러가 발생합니다. 카탈로그도, 컨트롤파일도 없으니 RMAN이 이 DB의 DBID를 알 길이 없기 때문입니다.

SET DBID 1200530011;
초기 상태 확인 시 메모해 두었던 DBID를 수동으로 세팅해 줍니다.

RESTORE CONTROLFILE FROM AUTOBACKUP;
DBID를 주고 다시 시도해도 이번엔 RMAN-06172 (백업 파일을 찾을 수 없음) 에러가 발생합니다. 자동 백업 경로를 오라클 기본 위치($ORACLE_HOME/dbs)가 아닌 사용자 정의 경로(/fra/backup/hotbackup/...)로 설정해서 쓰고 있었는데, 그 설정(CONFIGURE)값이 날아간 컨트롤파일 안에 들어있었기 때문에 RMAN이 엉뚱한 기본 경로만 뒤지다 실패한 것입니다.

SET CONTROLFILE AUTOBACKUP FORMAT FOR DEVICE TYPE DISK TO '/fra/backup/hotbackup/cf_%F';
자동 백업이 저장된 사용자 정의 경로 포맷을 세션에 수동으로 알려줍니다. (알려주신 핫 백업 경로 적용)

RESTORE CONTROLFILE FROM AUTOBACKUP;
DBID와 백업 경로를 모두 알게 된 RMAN이 마침내 컨트롤파일 복원에 성공합니다.

ALTER DATABASE MOUNT;

CATALOG START WITH '/fra/backup/hotbackup/';
CROSSCHECK BACKUP;
과거 시점의 컨트롤파일이 복원되었으므로, 그 이후에 받아둔 백업들의 존재를 이 컨트롤파일은 모릅니다. 따라서 백업 경로를 직접 스캔(CATALOG START WITH)하여 컨트롤파일에 메타데이터를 밀어 넣고 갱신(CROSSCHECK)해 줍니다.

RECOVER DATABASE;

ALTER DATABASE OPEN RESETLOGS;
```
