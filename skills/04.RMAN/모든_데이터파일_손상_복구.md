**복구 절차 : 오류 발생 → 원인 파악 → 수정**
[세션: RMAN (Target + Catalog 동시 접속)]
RECOVER DATABASE;
과거 파일 복원(RESTORE)을 빼먹고 곧바로 리두 적용(RECOVER)을 섣불리 시도해 봅니다. 복구 대상이 될 물리적인 과거 파일이 디스크에 존재하지 않으므로 오라클은 RMAN-06094 (먼저 복원부터 해라) 에러를 뱉고 단호하게 거절합니다.

RUN {
   ALLOCATE CHANNEL c1 DEVICE TYPE DISK;
   ALLOCATE CHANNEL c2 DEVICE TYPE DISK;
   ALLOCATE CHANNEL c3 DEVICE TYPE DISK;
   ALLOCATE CHANNEL c4 DEVICE TYPE DISK;
   RESTORE DATABASE;
   RECOVER DATABASE;
}

복원 및 복구 시간을 단축하기 위해 4개의 채널을 동시 다발적으로 할당하여 병렬 복구 세션을 구성합니다.
RESTORE DATABASE 명령이 컨트롤파일에 기록된 원래 경로를 찾아 누락된 디렉터리(/fra/oradata/ORCL/)까지 알아서 새로 생성해 가며 모든 데이터파일을 제자리에 완벽히 복원해 냅니다.
이어지는 RECOVER DATABASE가 아카이브 로그와 온라인 리두 로그를 순차적으로 자동 적용하여 1바이트의 유실도 없는 최신 동기화 상태로 롤포워드를 마칩니다.

ALTER DATABASE OPEN;
