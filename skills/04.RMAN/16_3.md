```sql
[1] 시나리오 개요
-- 데이터베이스 인스턴스를 기동하는 데 필수적인 초기화 파라미터 파일(spfile 및 pfile)이 모두 유실된 상황을 가정한다.
-- Oracle 19c RMAN의 향상된 기능(파라미터 파일 없이 최소 인스턴스 자동 기동)을 확인한다.
-- DBID와 자동 백업 경로를 수동으로 설정하여 컨트롤파일 자동 백업 조각에서 spfile을 복원한다.
-- 복구 유형 : 파라미터 파일 복구, 전면 중단

[2] 사전 조건
-- 컨트롤파일 자동 백업(AUTOBACKUP) 기능이 활성화되어 있어야 하며, 유효한 자동 백업 조각이 디스크에 존재해야 한다.

[oracle@oel7v9 ~]$ rman target / catalog rcatowner@rcat
RMAN> SHOW CONTROLFILE AUTOBACKUP;
RMAN> BACKUP DATABASE TAG 'BASE_163' PLUS ARCHIVELOG;
RMAN> EXIT
-- 백업 수행 시 컨트롤파일과 함께 spfile이 포함된 자동 백업(Autobackup) 피스가 생성된다.

[3] 초기 상태 확인
[oracle@oel7v9 ~]$ sqlplus / as sysdba
SYS@orcl> SHOW PARAMETER spfile
-- 현재 인스턴스가 사용 중인 spfile의 위치를 확인한다. 기본 경로는 $ORACLE_HOME/dbs/spfileorcl.ora이다.

SYS@orcl> SELECT dbid FROM v$database;
-- 파라미터 파일 유실 시 복원을 위해 필수적인 DBID를 사전 기록한다.

SYS@orcl> COL name  FOR a30
SYS@orcl> COL value FOR a40
SYS@orcl> SELECT name, value FROM v$parameter
2  WHERE  isdefault = 'FALSE' AND name IN
3    ('control_file_record_keep_time','log_archive_dest_1','sga_target');
-- 기본값이 아닌 변경된 주요 파라미터 값(예: sga_target)을 기록하여, 복원 후 유실 여부를 대조할 기준으로 삼는다.

[4] 장애 유발 : spfile 삭제
SYS@orcl> SHUTDOWN IMMEDIATE
SYS@orcl> !rm -f $ORACLE_HOME/dbs/spfileorcl.ora
SYS@orcl> !ls $ORACLE_HOME/dbs/orcl
-- 데이터베이스를 정상 종료한 뒤 운영 중인 spfile을 OS에서 삭제하여 장애를 유발한다. (pfile 사본도 존재하지 않는 상태를 가정한다.)

[5] 증상 관찰
SYS@orcl> STARTUP
-- ORA-01078, LRM-00109 에러가 발생하며 인스턴스 기동이 실패한다. 오라클은 spfile<SID>.ora → spfile.ora → init<SID>.ora 순으로 파라미터 파일을 찾는데, 모두 없으므로 실패하는 정상적인 증상이다.

[6] 진단
[oracle@oel7v9 ~]$ ls -lt /fra/backup/hotbackup/cf_* | head -2
-- 자동 백업 디렉터리 내 최신 백업 조각의 존재 및 파일명에 포함된 DBID를 확인한다.

[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
[oracle@oel7v9 ~]$ rman target /
RMAN> STARTUP NOMOUNT
-- 19c RMAN은 파라미터 파일이 없으면 starting Oracle instance without parameter file for retrieval of spfile 메시지와 함께 기본값(SGA 약 1GB 등)으로 더미(Dummy) 최소 인스턴스를 스스로 기동한다.

-- 테스트 1: DBID 설정 후 복원 시도
RMAN> SET DBID 1200530011;
RMAN> RESTORE SPFILE FROM AUTOBACKUP;
-- RMAN-06172(백업 파일을 찾을 수 없음) 에러가 발생한다. 자동 백업 경로 설정(CONFIGURE)값 역시 spfile과 컨트롤파일에 저장되어 있으므로, 현재 더미 인스턴스는 해당 설정을 알지 못해 기본 위치($ORACLE_HOME/dbs)만 탐색하다 실패한다.

-- 정상 복구 절차 수행 (경로 포맷 지정)
RMAN> SET CONTROLFILE AUTOBACKUP FORMAT FOR DEVICE TYPE DISK
2>   TO '/fra/backup/hotbackup/cf_%F';
RMAN> RESTORE SPFILE FROM AUTOBACKUP;
-- 자동 백업 위치와 이름 포맷을 수동으로 알려주어 올바른 백업 조각을 찾게 하고, spfile을 원래 기본 경로($ORACLE_HOME/dbs)로 무사히 복원한다.

RMAN> SHUTDOWN IMMEDIATE
RMAN> STARTUP
-- 더미 인스턴스를 내리고, 복원된 정상 spfile을 읽어 데이터베이스를 온전히 재기동(OPEN)한다.

[8] 검증 및 실무 포인트
RMAN> EXIT
[oracle@oel7v9 ~]$ sqlplus / as sysdba

SYS@orcl> SHOW PARAMETER spfile
SYS@orcl> SELECT name, value FROM v$parameter
2  WHERE  isdefault = 'FALSE' AND name IN
3    ('control_file_record_keep_time','log_archive_dest_1','sga_target');
-- SGA 크기 등 사용자가 변경했던 파라미터 값들이 백업 당시의 상태 그대로 온전하게 복구되었음을 확인한다.

SYS@orcl> CREATE PFILE='/home/oracle/backup/initorcl_20250518.ora' FROM SPFILE;
-- 재발 방지를 위해 현재 정상 상태의 spfile을 텍스트 기반의 pfile 사본으로 별도 경로에 백업해 둔다.

[oracle@oel7v9 ~]$ rman target / catalog rcatowner@rcat
RMAN> BACKUP DATABASE TAG 'AFTER_SPFILE' PLUS ARCHIVELOG;
RMAN> EXIT
-- 인스턴스 구성이 복원되었으므로 새로운 전체 백업을 수행하여 기준점을 갱신한다.
```
