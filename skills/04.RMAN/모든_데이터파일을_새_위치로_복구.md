-- 데이터 디스크 전체를 쓸 수 없어 새 디스크로 옮기며 복구한다.
-- SET NEWNAME FOR DATABASE 로 여러 파일을 한 번에 지정한다.
-- SWITCH DATAFILE ALL 로 컨트롤파일의 경로를 일괄 갱신한다.
-- 치환 문자 %b 의 동작을 확인한다.
-- 복구 유형 : 완전 복구, 전면 중단, 전체 경로 변경

**사전 조건**
[세션: Linux OS Shell]
mkdir -p /fra/oradata/ORCL
기존 데이터 디스크를 더 이상 쓸 수 없다고 가정하고, 모든 데이터파일을 수용할 새로운 스토리지 경로(/fra/oradata/ORCL/)를 사전에 준비합니다. (요청하신 사용자 경로 적용)

df -h /fra | tail -1

[세션: RMAN (Target + Catalog 동시 접속)]
BACKUP DATABASE TAG 'BASE_155' PLUS ARCHIVELOG;
실습을 위한 깨끗한 복구 기준점을 만들기 위해 전체 데이터베이스와 아카이브 로그 백업을 수행합니다.

**초기 상태 확인**
[세션: SQL*Plus (SYSDBA)]
SELECT file#, name FROM v$datafile ORDER BY file#;
현재 데이터파일들의 경로를 확인합니다. (기존 운영 경로인 /u02/oradata/orcl/ 등에 위치해 있음을 확인합니다.)

INSERT INTO hr.rec154 VALUES (3, 'before move');
COMMIT;
ALTER SYSTEM ARCHIVE LOG CURRENT;
장애 직전의 최신 트랜잭션을 생성하고 아카이브합니다.

**장애 유발 : 기존 운영 디스크 사용 불가**
[세션: SQL*Plus (SYSDBA)]
SHUTDOWN ABORT

!rm -f /u02/oradata/orcl/ *.dbf
운영 데이터 디스크 전체 장애를 가정하여 OS 상에서 모든 데이터파일(.dbf)을 삭제합니다.

!ls /u02/oradata/orcl/ *.dbf 2>/dev/null | wc -l
데이터파일이 모두 유실되었음을 확인합니다.

**증상 관찰**
[세션: SQL*Plus (SYSDBA)]
STARTUP MOUNT
컨트롤파일과 리두 로그는 손상되지 않았으므로 인스턴스는 MOUNT 단계까지 무사히 올라갑니다.

SELECT file#, error FROM v$recover_file ORDER BY file#;
모든 데이터파일이 FILE NOT FOUND 상태에 빠져 있음을 확인합니다. (이전 실습에서 옮겨둔 파일이 있다면 해당 파일 제외)

SELECT ROUND(SUM(bytes)/1024/1024) AS total_mb FROM v$datafile;
MOUNT 상태에서는 파일 헤더를 읽어 용량을 계산하려 시도하지만 물리적 파일이 없으므로 0으로 조회됩니다. 실제 필요 공간은 RMAN 카탈로그를 통해 산정해야 합니다.

**진단**
[세션: RMAN (Target + Catalog 동시 접속)]
REPORT SCHEMA;
카탈로그에 기록된 메타데이터를 바탕으로 각 데이터파일의 Size(MB)를 확인하여, 새 디스크(/fra/oradata/ORCL/)에 필요한 총 여유 공간을 계산하고 검토합니다.

RESTORE DATABASE PREVIEW SUMMARY;
전체 데이터베이스 복원에 필요한 백업 피스와 롤포워드(Roll-forward)에 필요한 아카이브 로그가 온전히 있는지 가상으로 점검합니다.

**복구 절차 : 오류 발생 → 원인 파악 → 수정**
[세션: RMAN (Target + Catalog 동시 접속)]

RUN {
   SET NEWNAME FOR DATABASE TO '/fra/oradata/ORCL/';
   RESTORE DATABASE;
}
수십 개의 파일마다 SET NEWNAME을 일일이 치는 대신 FOR DATABASE를 사용하여 디렉터리만 통째로 줘봅니다. 오라클은 RMAN-06970 에러를 뱉으며, 파일명을 동적으로 생성할 수 있는 포맷(치환 문자 %f나 %U)을 반드시 포함하라고 지시합니다.

RUN {
   SET NEWNAME FOR DATABASE TO '/fra/oradata/ORCL/%b';
   RESTORE DATABASE;
   SWITCH DATAFILE ALL;
   RECOVER DATABASE;
}

디렉터리 경로 뒤에 %b (원래 파일명만 추출하여 유지하는 치환 문자)를 붙여 에러를 수정하고 실행합니다.

SET NEWNAME: 타겟 복원 경로를 원래 파일명(%b)을 유지한 채 새 디스크(/fra/oradata/ORCL/)로 설정합니다.

RESTORE DATABASE: 모든 데이터파일을 해당 새 디스크 위치로 물리적으로 복원해 냅니다.

SWITCH DATAFILE ALL: 컨트롤파일에 기록된 모든 데이터파일의 기존 포인터 경로를 새 위치로 일괄 갱신합니다.

RECOVER DATABASE: 아카이브 및 리두 로그를 적용해 최신 상태로 동기화합니다.

ALTER DATABASE OPEN;
복구가 완료된 후 데이터베이스를 정상 오픈합니다.
